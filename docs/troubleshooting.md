# Argus Sensor Troubleshooting Guide

**Scope:** Argus sensor only. Issues specific to client programs (`ra`, `radump`, etc., from the
`argus-clients` repo) are out of scope — see the note at the end of each relevant section.

---

## Installation Issues

### Problem: `./configure` fails — `libpcap not found`

```bash
# Ubuntu/Debian
sudo apt-get install libpcap-dev
# Fedora/RHEL
sudo dnf install libpcap-devel
# macOS
brew install libpcap
```

```bash
./configure --with-pcap=/usr/local
```

### Problem: `make` fails — missing `argus_config.h`

```bash
./configure
make
```

`argus_config.h` is generated by `./configure`; if it's missing, `configure` didn't complete successfully
— check its output for errors first.

### Problem: `make install` — permission denied

```bash
sudo make install
# or:
./configure --prefix=$HOME/.local && make && make install
```

## Capture Problems

### Problem: No packets captured

```bash
ip link show eth0          # confirm interface exists and is up
sudo tcpdump -i eth0 -c 10 # confirm traffic actually reaches the interface
```

```bash
sudo setcap cap_net_raw,cap_net_admin=eip $(which argus)
# or run as root:
sudo argus -i eth0
```

### Problem: `pcap_activate failed: Operation not permitted`

```bash
sudo argus -i eth0
# or, on Linux:
sudo setcap cap_net_raw,cap_net_admin+eip $(which argus)
```

Also check AppArmor/SELinux if capture still fails after granting capabilities.

### Problem: Filter doesn't work as expected

**Dump the compiled filter:**
```bash
sudo argus -i eth0 -b 'tcp port 80'
```
`-b` (`argus/argus.c`, `Argusbpf_dump` in `ArgusSource.c`) dumps the BPF filter compiler output, which is
the correct way to debug a filter expression that isn't matching what you expect.

**Compare against tcpdump using the same expression:**
```bash
tcpdump -i eth0 'tcp port 80' -c 10
```
Argus compiles filters via the same libpcap `pcap_compile()` call tcpdump uses (`ArgusSource.c`). If
tcpdump matches the traffic you expect but Argus doesn't, the filter expression itself is not the problem
— look at interface selection or `-e`/monitor-ID configuration instead.

**Quoting:** always quote multi-word filter expressions to avoid shell word-splitting:
```bash
argus -i eth0 'tcp port 80'      # correct
argus -i eth0 tcp port 80        # wrong — shell splits this into separate argv entries
```

### Problem: High packet loss

```bash
# Increase kernel-level socket buffer limits (Linux)
sudo sysctl -w net.core.rmem_max=134217728
sudo sysctl -w net.core.rmem_default=134217728
```

Standard Linux kernel tuning for high-volume packet capture (not Argus-specific).

**Increase the pcap capture buffer directly:**
```conf
ARGUS_PCAP_BUF_SIZE=1G
```
Accepts `K`/`M`/`G` suffixes. See `docs/configuration.md`.

CPU pinning (`taskset -c 0 argus -i eth0`) can help on multi-core systems but is a generic OS mechanism,
not an Argus feature.

## Configuration Issues

### Problem: Configuration file not read

**Check the only automatically-searched location:**
```bash
ls -la /etc/argus.conf
```
`/etc/argus.conf` is the only file the sensor loads automatically, and only if it exists — see
`docs/architecture.md` §7 and `docs/configuration.md` §2. There is no `$ARGUSPATH`/`$HOME`-based
auto-search in this version.

**Load an explicit config file instead:**
```bash
argus -F /path/to/argus.conf -i eth0
```

**Check syntax — no spaces around `=`:**
```conf
ARGUS_DAEMON=yes    # correct
ARGUS_DAEMON = yes  # wrong
```

**Check variable names against the reference list** in `docs/configuration.md` §3 — a typo'd or
non-existent variable name is silently ignored by the config parser, not flagged as an error you'd
necessarily notice.

### Problem: Interface not found

```bash
ip link show
# or
ifconfig -a
```

```bash
argus -i all
```

`-i all` is a minimal way to reference every interface; see the richer syntax in
`docs/configuration.md` §4 (e.g. `-i ind:all` for independent per-interface tracking) if you need
explicit control over how multiple interfaces are combined.

### Problem: Output file not created

```bash
ls -ld /var/log/argus/     # writable by the argus user?
df -h /var/log/            # disk space?
```

```bash
# Use an absolute path
argus -i eth0 -w /var/log/argus/data.argus
```

```bash
# Write to stdout to confirm the sensor is producing output at all
argus -i eth0 -w -
```

## Performance Problems

### Problem: High CPU usage

**Simplify the capture filter** to reduce per-packet processing:
```bash
argus -i eth0 'tcp or udp'
```

**Reduce flow-key complexity** if using an expanded key:
```conf
ARGUS_FLOW_KEY=CLASSIC_5_TUPLE
```

**Tune the MAR/status-report intervals** if reporting overhead matters at scale:
- `-M <secs>` sets the MAR (management/status record) report interval (default 300s). MAR records
  contain sensor health/performance data (packet counts, drops, queue depth — see `docs/data-model.md`
  §6); `-M` controls how often that data is emitted.
- `-S <secs>` sets the flow-status report interval (default 60s), independent of `-M`.

### Problem: Memory exhaustion

```conf
# Reduce how long idle flows are retained in the flow cache
ARGUS_TCP_TIMEOUT=60
ARGUS_IP_TIMEOUT=30
```

There is no direct flow-count cap variable. Memory pressure from flow-table growth is controlled
indirectly via the per-protocol timeout variables (`ARGUS_IP_TIMEOUT`, `ARGUS_TCP_TIMEOUT`, etc. — full
list in `docs/configuration.md` §3) and `ARGUS_HASHTABLE_SIZE`, which affects lookup performance rather
than imposing a hard memory ceiling.

```bash
# Check for actual memory leaks (generic tool, not Argus-specific)
valgrind --leak-check=full argus -r test.pcap
```

### Problem: Slow output writing

```bash
argus -i eth0 -w argus-udp://collector.example.com:561
```

Remote streaming output uses `-w argus-udp://host[:port]` (default port **561** — see
`include/argus_int.h`, `#define ARGUS_PORT 561`). See `docs/architecture.md` §6 and
`docs/configuration.md` §3 (`ARGUS_OUTPUT_STREAM`) for the two real remote-output mechanisms.

There is no built-in output compression variable; piping through `gzip` on the shell side
(`argus -w - | gzip`) is possible but is a shell-level technique, not an Argus feature.

## Output/Data Issues

**This section is scoped to sensor-side causes only.** Interpreting/reading flow record content requires
client tools (`ra`, `radump`) from the separate `argus-clients` repo, which is out of scope for this
document. If flow records look wrong, first isolate whether the problem is in the sensor's
classification/capture (in scope here) or in a client's interpretation of the record (out of scope here,
check the clients repo).

### Problem: Suspected wrong byte counts / missing timestamps / wrong protocol detection (sensor side)

**Confirm packets are actually being captured correctly, independent of Argus:**
```bash
sudo tcpdump -i eth0 -c 100 -w test.pcap
```
Then feed the same pcap to Argus (`-r test.pcap`) and compare — if Argus's classification of that exact
packet capture looks wrong, that's a sensor-side (in-scope) issue; if raw capture itself looks wrong,
that's an OS/interface/tcpdump-level issue, not Argus.

**Check flow directionality setting:**
```conf
ARGUS_FLOW_TYPE=Uni
```
`ARGUS_FLOW_TYPE` is a config-file variable only, with no command-line-flag equivalent — set it in a
config file loaded via `-F`.

### Problem: Missing metrics in output (sensor side)

Several metrics require an explicit feature toggle in `argus.conf` before the sensor will generate them
at all (see `docs/configuration.md` §3 for the complete list):

```conf
ARGUS_GENERATE_JITTER_DATA=yes
ARGUS_GENERATE_APPBYTE_METRIC=yes
ARGUS_GENERATE_MAC_DATA=yes
```

If a metric is still missing after confirming the right toggle is set, the next thing to check is whether
the metric is even applicable to the flow's protocol — see the "Produced by: Sensor" column in
`docs/data-model.md` §4 for which DSRs exist for which protocols.

## Debugging Tools

### Argus debug output

```bash
argus -i eth0 -D 3
```

`-D <level>` is a purely numeric debug level (parsed with `atoi()`), and only available if the sensor was
built with `ARGUSDEBUG` defined.

### System-level debugging (generic, not Argus-specific)

```bash
strace -f -p $(pidof argus)      # Linux
dtruss -p $(pidof argus)          # macOS
```

### Checking what the sensor is listening on

```bash
netstat -an | grep 561
```

The default port is **561**, for both `-P <portnum>` remote access and the default `argus-udp://` stream
port — see `docs/configuration.md` §3, `ARGUS_ACCESS_PORT`.

## Common Error Messages

| Symptom | Likely cause | Where to look |
|---|---|---|
| `pcap_activate failed: Operation not permitted` | Missing packet-capture privilege | §"Capture Problems" above |
| Interface not found | Wrong name, or OS renamed it | `ip link show` / `ifconfig -a` |
| Sensor exits immediately with usage text | Unrecognized flag passed | Re-check flag against `argus -h` output or `docs/configuration.md` |
| Config values not applied | Typo'd variable name, or expecting env-var/`$HOME` config support that doesn't exist | §"Configuration Issues" above |
| `Can't bind` / port in use | Another process (or another `argus`/`radium` instance) already on that port | Check `ARGUS_ACCESS_PORT`, use `-P <other-port>` |

File-format/version-mismatch errors between sensor output and client tools (`ra`, `radump`) are a
client-side troubleshooting topic and out of scope here.

## Getting More Help

```bash
uname -a
argus -h
cat /etc/os-release
```

```bash
cat /etc/argus.conf
```

To check whether a config file will be accepted without actually running a full capture, run in the
foreground with a high debug level:
```bash
argus -F /etc/argus.conf -D 3 -d
```
and observe the startup log output.

```bash
./bin/argusbug
```
`bin/argusbug` is the documented, preferred way to file a bug report (per `CONTRIBUTING.md` and
`README.md`).

Mailing list: `argus-info@lists.andrew.cmu.edu` (per `README.md`).
